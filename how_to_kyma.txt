1. install docker desktop, check cli

    docker --version
    kubectl version --client
    kubectl config get-contexts

2. create kubernetes cluster in docker desktop, check nodes and pods in terminal

    kubectl config get-contexts
    kubectl get nodes
    kubectl get pods -A

3. create any app (py_test)

4. create a docker image with your app

    docker build -t idhaunter/kyma_lab:3.12_00 .
    docker run -it --rm -e PY_TEST_LOG_LEVEL=DEBUG -p 3000:3000 idhaunter/kyma_lab:3.12_00
    docker ps -a
    docker image ls
    docker stop <container_id>
    docker rmi <image_id>
    docker push docker.io/idhaunter/kyma_lab:3.12_00

5. create kubernetes deployment configuration in deployment.yaml

```
apiVersion: apps/v1
kind: Deployment

metadata:
  name: kyma-lab

spec:
  replicas: 1

  selector:
    matchLabels:
      app: kyma-lab

  template:
    metadata:
      labels:
        app: kyma-lab

    spec:
      containers:
        - name: kyma-lab
          image: idhaunter/kyma_lab:3.12_00
          ports:
            - containerPort: 3000
```

6. Apply deployment configuration

    kubectl apply -f deployment.yaml
    kyma_lab % kubectl get deployments

    Now we have a docker running in the pod.
    But for now, there is one important thing: the application cannot yet be properly accessed from within Kubernetes from outside the Pod. To enable this, the next step is to create a Service.

```
Kubernetes cluster
│
└── Deployment: kyma-lab
       │
       └── ReplicaSet
              │
              └── Pod
                    │
                    └── Container
                          │
                          └── FastAPI :3000

```

7. Creating a service. Pod has dynamic IP, we need a service as stable point of access.

    kubectl get pods                                    (here you can see a pod name)
    kubectl describe pod kyma-lab-697dcddd46-lvmlw      (pod description)
    kubectl logs kyma-lab-697dcddd46-lvmlw              (pod logs)

    Create a file "service.yaml" in one directory with "deployment.yaml".
    It says - traffic must go into pods with label "kyma-lab"

```
apiVersion: v1
kind: Service

metadata:
  name: kyma-lab

spec:
  selector:
    app: kyma-lab

  ports:
    - protocol: TCP
      port: 3000
      targetPort: 3000
```

    kubectl apply -f service.yaml
    kubectl get services

    kubectl port-forward service/kyma-lab 3000:3000  (in one terminal)
    curl http://localhost:3000/                      (in another terminal)

```
curl
 ↓
localhost:3000
 ↓
kubectl port-forward
 ↓
Kubernetes Service
 ↓
Pod
 ↓
FastAPI
```

9. Kill one pod and see what will happen - kubernetes will create new automatically

    kubectl get pods

10. Provide resources (env variables) for deployment and pods within.
    Create configmap.yaml file

```
apiVersion: v1
kind: ConfigMap

metadata:
  name: kyma-lab-config

data:
  PY_TEST_LOG_LEVEL: "DEBUG"
```

    kubectl apply -f configmap.yaml
    kubectl describe configmap kyma-lab-config

11. Connect ConfigMap to the deployment. Add to deployment.yaml

```
env:
- name: PY_TEST_LOG_LEVEL
  valueFrom:
    configMapKeyRef:
      name: kyma-lab-config
      key: PY_TEST_LOG_LEVEL
```

    kubectl apply -f deployment.yaml     (apply changes)

12. Check that variable exists in the pods

    kubectl get pods
    kubectl exec <pod-name> -- env | grep PY_TEST_LOG_LEVEL
    kubectl exec kyma-lab-6d667f7d7c-qj775 -- env | grep PY_TEST_LOG_LEVEL

13. Change variable and restart deployment

    PY_TEST_LOG_LEVEL: "INFO"
    kubectl apply -f configmap.yaml
    kubectl exec kyma-lab-6d667f7d7c-qj775 -- env | grep PY_TEST_LOG_LEVEL (here will be OLD value)
    kubectl rollout restart deployment kyma-lab
    kubectl exec kyma-lab-6d667f7d7c-qj775 -- env | grep PY_TEST_LOG_LEVEL (here will be NEW value)
