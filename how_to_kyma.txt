1. install docker desktop, check cli

    docker --version
    kubectl version --client
    kubectl config get-contexts

2. create kubernetes cluster in docker desktop, check nodes and pods in terminal

    kubectl config get-contexts
    kubectl get nodes
    kubectl get pods -A

3. create any app (py_test)

4. create a docker image with your app

    docker build -t idhaunter/kyma_lab:3.12_01 .
    docker run -it --rm -e PY_TEST_LOG_LEVEL=DEBUG -p 3000:3000 idhaunter/kyma_lab:3.12_01
    docker ps -a
    docker image ls
    docker stop <container_id>
    docker rmi <image_id>
    docker push docker.io/idhaunter/kyma_lab:3.12_01

5. create kubernetes deployment configuration in deployment.yaml

```
apiVersion: apps/v1
kind: Deployment

metadata:
  name: kyma-lab

spec:
  replicas: 1

  selector:
    matchLabels:
      app: kyma-lab

  template:
    metadata:
      labels:
        app: kyma-lab

    spec:
      containers:
        - name: kyma-lab
          image: idhaunter/kyma_lab:3.12_00
          ports:
            - containerPort: 3000
```

6. Apply deployment configuration

    kubectl apply -f deployment.yaml
    kubectl get deployments

    Now we have a docker running in the pod.
    But for now, there is one important thing: the application cannot yet be properly accessed from within Kubernetes from outside the Pod. To enable this, the next step is to create a Service.

```
Kubernetes cluster
│
└── Deployment: kyma-lab
       │
       └── ReplicaSet
              │
              └── Pod
                    │
                    └── Container
                          │
                          └── FastAPI :3000

```

7. Creating a service. Pod has dynamic IP, we need a service as stable point of access.

    kubectl get pods                                    (here you can see a pod name)
    kubectl describe pod kyma-lab-697dcddd46-lvmlw      (pod description)
    kubectl logs kyma-lab-697dcddd46-lvmlw              (pod logs)

    Create a file "service.yaml" in one directory with "deployment.yaml".
    It says - traffic must go into pods with label "kyma-lab"

```
apiVersion: v1
kind: Service

metadata:
  name: kyma-lab

spec:
  selector:
    app: kyma-lab

  ports:
    - protocol: TCP
      port: 3000
      targetPort: 3000
```

    kubectl apply -f service.yaml
    kubectl get services

    kubectl port-forward service/kyma-lab 3000:3000  (in one terminal)
    curl http://localhost:3000/                      (in another terminal)

```
curl
 ↓
localhost:3000
 ↓
kubectl port-forward
 ↓
Kubernetes Service
 ↓
Pod
 ↓
FastAPI
```

10. Provide resources (env variables) for deployment and pods within.
    Create configmap.yaml file

```
apiVersion: v1
kind: ConfigMap

metadata:
  name: kyma-lab-config

data:
  PY_TEST_LOG_LEVEL: "DEBUG"
```

    kubectl apply -f configmap.yaml
    kubectl describe configmap kyma-lab-config

11. Connect ConfigMap to the deployment. Add to deployment.yaml

```
env:
- name: PY_TEST_LOG_LEVEL
  valueFrom:
    configMapKeyRef:
      name: kyma-lab-config
      key: PY_TEST_LOG_LEVEL
```

    kubectl apply -f deployment.yaml     (apply changes)

12. Check that variable exists in the pods

    kubectl get pods
    kubectl exec <pod-name> -- env | grep PY_TEST_LOG_LEVEL
    kubectl exec kyma-lab-6d667f7d7c-qj775 -- env | grep PY_TEST_LOG_LEVEL

13. Change variable and restart deployment

    PY_TEST_LOG_LEVEL: "INFO"
    kubectl apply -f configmap.yaml
    kubectl exec kyma-lab-6d667f7d7c-qj775 -- env | grep PY_TEST_LOG_LEVEL (here will be OLD value)
    kubectl rollout restart deployment kyma-lab
    kubectl exec kyma-lab-6d667f7d7c-qj775 -- env | grep PY_TEST_LOG_LEVEL (here will be NEW value)

16. Modify configmap.yaml - here is the link to value config.logLevel from values.yaml

```

kind: ConfigMap

metadata:
  name: {{ .Release.Name }}-config

data:
  PY_TEST_LOG_LEVEL: "{{ .Values.config.logLevel }}"
```

26. Install loki using helm

    kubectl config current-context        - check current context (must be docker-desktop)
    kubectl get nodes                     - get nodes
    kubectl create namespace monitoring   - create namespace
    kubectl get namespaces                - to see all namespaces

    helm repo list                        - get helm repositories list

    helm repo add grafana https://grafana.github.io/helm-charts       - add Grafana Helm repository
    helm repo update                                                  - update to actual versions
    helm repo list
    helm search repo grafana/loki                                     - check Grafana loki

    create directory "monitoring" and file "loki-values.yaml" inside of it

    helm show values grafana/loki > loki-values-default.yaml   - check loki defaults
    helm show chart grafana/loki                               - current chart version

    helm install loki grafana/loki --namespace monitoring --values loki-values.yaml      - install loki

    helm list -n monitoring    - checking, should be like this:

    NAME    NAMESPACE       REVISION        UPDATED                                 STATUS          CHART           APP VERSION
    loki    monitoring      1               2026-09-20 15:05:53.972373 +0200 CEST   deployed        loki-7.3.0      3.6.12

    kubectl get pods -n monitoring      - check all pods created for loki
    kubectl get all -n monitoring       - check all resources for loki

    kubectl port-forward -n monitoring svc/loki 3100:3100      - in one terminal
    curl http://localhost:3100/ready                           - in second terminal
    curl http://localhost:3100/loki/api/v1/status/buildinfo
    curl http://localhost:3100/metrics
